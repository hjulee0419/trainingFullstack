# TodoList 화면 와이어프레임

버전: 1.2 / 작성일: 2026-07-29 / 수정일: 2026-07-29

참조: `2-PRD.md`(FR-1~FR-13), `3-user-scenario.md`(페르소나/시나리오), `4-project-structure.md`(routes/ 구조)

## 1. 문서 개요

- 본 문서는 `4-project-structure.md`의 `routes/` 하위 7개 화면에 대한 텍스트 기반(ASCII) 와이어프레임을 정의한다.
- 목적: 실제 구현(React 19 + TS) 착수 전 레이아웃 구조(헤더/네비게이션, 폼, 목록, 필터바 위치 등)를 빠르게 합의하기 위함이며, 그래픽 목업 도구는 사용하지 않는다.
- 기준 해상도: 확정 스택(React 19 + TS, PC/태블릿/모바일 브라우저를 아우르는 반응형 웹, 네이티브 앱 없음)에 맞춰 **전 화면(S1~S7)에 대해 데스크톱 버전과 모바일 버전 와이어프레임을 함께 제시**한다. 모바일 버전은 각 화면의 데스크톱 와이어프레임 바로 아래 하위 절로 배치한다.
- 접근성(A11y)은 PRD 6.5·4.3에서 범위 외로 명시되어 본 문서에서도 다루지 않는다.
- 각 화면 제목에 관련 FR 번호를 병기해 추적성을 확보한다.

## 5. S3. 할일 목록 화면 — 데스크톱 (FR-5, FR-11)

```
┌───────────────────────────────────────────────────────────────────┐
│ TodoList     [할일 목록] [카테고리] [계정]              user@mail ▾  │ ← GNB
├───────────────────────────────────────────────────────────────────┤
│ 필터  카테고리:[전체 ▾]  상태:[전체 ▾]  (AND 조건)   [+ 새 할일]     │ ← 필터바(가로)
├───────────────────────────────────────────────────────────────────┤
│ ┌───────────────────────────────────────────────────────────────┐ │
│ │ [진행중] 데이터베이스 프로젝트 보고서          [과제]           │ │
│ │ 2026-07-25 ~ 2026-08-05                                       │ │
│ ├───────────────────────────────────────────────────────────────┤ │
│ │ [기한초과] 협력사 미팅 자료 준비              [마케팅 캠페인]    │ │
│ │ 2026-07-10 ~ 2026-07-20                                       │ │
│ ├───────────────────────────────────────────────────────────────┤ │
│ │ [완료] 동아리 회비 납부           완료일시 2026-07-22 14:03 [기본]│ │
│ │ 2026-07-01 ~ 2026-07-20                                       │ │
│ ├───────────────────────────────────────────────────────────────┤ │
│ │ [시작 전] 7월 SNS 콘텐츠 기획              [마케팅 캠페인]      │ │
│ │ 2026-08-01 ~ 2026-08-10                                       │ │
│ └───────────────────────────────────────────────────────────────┘ │
│                                                                     │
│                     [ ← 이전 ]  1 2 3  [ 다음 → ]                  │ ← 페이지네이션
└───────────────────────────────────────────────────────────────────┘
```

- GNB: 서비스명 + 메뉴(할일 목록/카테고리/계정) + 로그인 사용자 표시(로그아웃 포함 드롭다운).
- 필터바: 카테고리 셀렉트 + 상태 셀렉트를 AND로 동시 적용(FR-5). 우측에 "새 할일" 버튼 → S4(등록)로 이동.
- 목록 항목(`TodoListItem`): 상태 뱃지(`TodoStatusBadge` — 시작 전/진행중/완료/기한초과), 제목, 카테고리 표시, 시작~종료일자, 완료 시 완료일시(FR-11) 표시.
- 항목 클릭 시 S4(수정)로 이동.
- 목록 하단 페이지네이션(FR-5 — 대량 데이터 조회 성능 보호).
- 목록이 비어있을 경우 `EmptyState` 컴포넌트로 "등록된 할일이 없습니다" 안내.

## 10. 공용 UI 요소 메모

- 헤더/GNB(`AppLayout`)는 S3~S7에서 공통 사용, S1~S2는 비인증 상태로 GNB 없이 카드형 레이아웃만 노출.
- GNB는 데스크톱에서 가로 메뉴(할일 목록/카테고리/계정 + 사용자 드롭다운)로 표시되고, 모바일(좁은 뷰포트)에서는 햄버거(☰) 토글 메뉴로 전환된다. 이 반응형 전환 규칙은 S3~S7 전 화면에 동일하게 적용해 일관성을 유지한다(5.1, 6.1, 7.1, 8.1, 9.1 참조). GNB "계정" 클릭 시 이동 대상은 S6(내 정보 조회)이며, S7은 S6의 "정보 수정" 버튼을 통해서만 진입한다.
- S1~S2(비인증 카드 폼)는 모바일에서 카드가 화면 폭 전체(좌우 패딩만 남김)로 늘어나고 입력 필드·버튼이 풀와이드로 표시되는 원칙을 공통 적용한다(3.1, 4.1 참조).
- 로딩/에러/빈 상태는 공통 컴포넌트(`LoadingSpinner`, `ErrorMessage`, `EmptyState`, `ConfirmDialog`)로 전 화면에서 재사용한다(`4-project-structure.md` 6.3, 8장 `shared/` 참조).
- 401(미인증) 발생 시 모든 화면에서 공통적으로 S1(로그인)로 리다이렉트, 404(소유자 아님)는 "존재하지 않는 항목입니다" 형태의 안내로 처리(도메인 규칙 4, FR-10).
